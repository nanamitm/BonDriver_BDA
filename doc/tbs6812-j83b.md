# TBS6812 J.83 Annex B（スカパー！プレミアムサービス光）

2026-10-31、`codex/tbs6812-isdb-t` の `d5b216a` から
`codex/tbs6812-j83b` を作成して追加した。

## 対応範囲と設定

対象は日本の光配信向け **5.6 Msym/s・6 MHz幅のJ.83 Annex B**。
北米の5.057/5.361 Msym/s版、およびJ.83 Annex Cはこの追加の対象外。
TBS6812のWindowsドライバーには独立したJ.83Bモードがないため、
カード側は地デジモード（値1）のまま、復調器をコア0x08へ直接切り替える。
カード全体のモード変更やコールドリセットはDLL内では行わない。

ビルド後、同じフォルダーに次の3ファイルを置く。

- `BonDriver_BDA.dll` を `BonDriver_BDA.J83B.dll` に変更したもの
- `config/BonDriver_TBS6812_J83B.ini` を `BonDriver_BDA.J83B.ini` に変更したもの
- 新しい `TBS6812.dll`

```ini
[TBS6812]
DeliverySystem="J.83B"
BootstrapFrequencyKHz=473143
LockTimeoutMs=3000
```

空き入力の自動選択と、FriendlyName末尾0/1による固定指定に対応。
ISDB-T/J.83Bは地デジモードの入力を共用する。同一入力を同時には使えない。
もう一方の入力が衛星モードなら、S/S3用として使用できる。

**今回の方式は、同じ入力で受信できる地デジの搬送波を初期準備に必要とする。**
デフォルトの473143 kHzはUHF13。地域に合わせて受信可能なUHF周波数に変更する。
光信号だけを入力し、地デジが全く受信できない構成は、この準備経路では動かない。
その構成にはBDAグラフを未選局で開始する別の初期化経路が必要。
起動キャッシュは使用しない。

テンプレートのOpticast自動生成はH001～H105と補助周波数を含む。
旧自動生成にないH044+2.2 MHz（374.95 MHz）はCH110に明示した。
入力する中心周波数を使用中の光サービスに合わせること。
通常の188バイトTSをTVTest/EDCBへ直接渡す。dantto4kには通さない。
限定受信・視聴処理は既存のスカパー光用のアプリ／カード設定が担当する。

## 初期準備・選局・復元

最初の選局時は、PreLockChannelでBDAへ渡す周波数・変調・識別情報を
一時的に地デジ用へ置き換える。PostLockChannelでアプリ側の指定を元に戻す。
地デジのロックが1.2秒連続して安定するまで、最大5秒待ってから引き継ぐ。
ロック直後に切り替えると、遅れて動く公式ドライバーの初期処理と干渉する例があった。

地デジのsleep処理、J.83Bの起動、3.75 MHz IF、5.6 Msym/sの固定探索範囲、
光配信用Freiaフィルター、パラレルTSクロックを設定する。
変更対象は当該入力の復調器とRFチューナーに限り、共有REFOUT/GPIOには触らない。
以後の選局はRF変更とソフト再捕捉だけで行う。

ロックはコア0x08を確認したうえで、bank 40/88のQAM同期と40/10のTSロックを見る。
C/Nは40/19のコンスタレーションと40/4Cの測定値から算出する。
ゼロ測定値は未測定として扱い、読み取り失敗時もfreezeを解除する。

終了時はJ.83Bの終了処理と地デジコアの起動処理を実行し、保存した公式ドライバーの
レジスター値・元の地デジ周波数・出力設定を復元する。地デジの再ロックも最大3秒確認する。
単にレジスター値を戻すだけでは地デジが復帰しない例があり、この起動処理が必要だった。
途中のI2C失敗でも、保存できた状態を使って地デジへの復元を試みる。
異常終了によるハードウェア状態の復旧は未検証。

## 検証記録

- Release_Static x64ビルドと既存テストを含む `tools/test-tbs6812.cmd` が成功。
- 模擬I2CでJ.83Bコア・IF・探索範囲・RF設定、同期とロック、C/N、freeze解除、
  全変更レジスターの復元、切り替え途中の失敗からの復元、共有参照クロックを変更しないことを確認。
- 実機で112.75 / 119.25 / 281.75 / 288.25 MHzを受信。
  安定部分のTSIDはそれぞれ0x3017 / 0x3019 / 0x3018 / 0x3020。
- 初回SetChannelは地デジ準備・安定待ちを含め約5.2～5.8秒。
  以後の直接選局は約0.20～0.23秒。OpenTunerの時間は別。
- 取得TSからWOWOW、TBS NEWS、BBCニュース、J SPORTSなどのサービス情報を確認。
  これはTS受信の確認であり、TVTestでの復号・映像音声確認ではない。
- 未受信の314.25 MHzから同じオープンのまま正常な4搬送波へ切り替えて受信し、
  J.83Bの再オープンも確認。
- J.83B終了後、設置済みの地デジ用BonDriverで13→14chの受信復帰を確認。
- 最終試験時はEDCBが入力1を使用していたため、試験用のS3ホルダーは排他により開けず、
  EDCBは停止しなかった。専用の同時受信試験スクリプトは準備したが、この試験の完走は未確認。

初期準備の地デジTSや、選局前のTSが先頭に混ざる場合がある。
先頭のPATだけで対象TSIDを判定せず、安定部分も調べる必要がある。
既存のS/T/S3と共通する選局境界の改善課題。最終試験の4搬送波は、先頭3 MiBを
除いた部分で同期・TEI・連続性エラーが0だった。固定量を捨てる対策は行っていない。
長時間録画・異常終了・J.83Bを2入力で同時使用する試験も残る。

両入力が空いており、入力0=地デジ＋光、入力1=衛星の場合の試験手順：

```powershell
cmd /c tools\build-probe.cmd work\bon-driver-probe-isdbt.exe
./tools/test-j83b-tbs6812.ps1 -RunHardwareTests
```

このスクリプトはモード変更を行わない。結果はwork/j83b-resultsに保存する。
本番のTVTest/EDCB用DLLはこの追加実装では更新していない。

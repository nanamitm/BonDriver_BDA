# TBS6812 ISDB-S3 残課題

更新日：2026-10-30

通常の視聴に必要な直接選局、2チューナー同時使用、空きチューナーの自動選択、
INIによる固定指定は実装済み。ユーザーにより2画面のライブ表示、および自動選択版の
TVTest視聴に問題がないことを確認済み。以下は未完了の検証・改善として残す。

## 検証

- [ ] **長時間の同時録画**
  - 2チューナーで異なる番組を数時間録画し、4Kと8Kの組み合わせも確認する。
  - 生TLV/MMTPの同期・連番、変換後TSの連番・TEI、映像音声の再生、停止やメモリー増加を確認する。
  - 片方の選局・録画終了・再オープンが、もう片方の録画に影響しないか確認する。
  - 現時点の短時間の同時受信試験を、長時間録画の確認済みとは扱わない。

- [ ] **異常終了後の復旧**
  - 試験用の受信プロセスを強制終了し、共通BonDriverでチューナーを再取得できるか確認する。
  - もう片方の受信継続、排他取得の解放、再取得後の選局・正常終了を確認する。
  - 自動選択と固定指定の両方で試す。通常終了後の再利用は確認済みだが、異常終了後は未確認。

## 改善

- [ ] **選局直後の旧データ混在を減らす**
  - 一部の切り替え試験で、短い旧ストリームの残り、旧PAT、連番飛びを観測した。
  - 生データ、BDAの受信バッファ、dantto4kの変換処理のどこに残るか切り分ける。原因は未確定。
  - 同一周波数の別TS、異なる周波数、4K・8K間の切り替えで確認する。
  - 対策後は、目的のTSID・サービスへの切り替わりと、安定後の連続性・選局時間を検証する。
  - 受信を続ける相手側への影響は、これまでの短時間試験では観測していない。

- [ ] **初回選局の短縮を検討する（任意の追加開発）**
  - 現在は各オープン後の初回だけ従来ドライバーで初期化するため、約9秒かかる。
  - 2026-10-30に両チューナー各3回を計測し、BDAの本選局呼び出し1回に約8.59～8.62秒かかると確認。予備選局は実行されていない。
  - ToneSignalWait=0の追加比較では約0.1秒の短縮に留まった。[計測結果](tbs6812-first-tune-timing.md)を参照。
  - 初期化済み状態を保存・検証して再利用する試作で、再オープン後の初回4Kを約1.0秒、8Kを約0.7秒にできた。[調査結果](tbs6812-warm-start-research.md)を参照。本番には未適用で、コールドスタートと新経路の品質・運用検証は残る。
  - 短縮には初期化経路の調査が必要。初期化全体の直接制御を採用するかは調査後に判断する。
  - 共有クロック・LNB電源・相手チューナーへの影響と、従来ドライバーへの復帰を確認する。
  - 視聴機能の未実装とは区別し、通常運用に必須の作業には含めない。

ISDB-S・地上波への対応は別機能として扱う。
現在の実装・設定・既存試験の詳細は [tbs6812-direct.md](tbs6812-direct.md) を参照。

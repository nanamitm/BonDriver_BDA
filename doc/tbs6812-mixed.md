# 同じBonDriverで地デジ・J.83BとISDB-Sを選ぶ

`config/BonDriver_TBS6812_TS.ini`を使うと、1つのBonDriverでUHF、スカパー光、BS、CS110を選局できる。
ISDB-S3とdantto4kは対象外で、従来の構成を使う。**両入力に地上波・衛星の混合信号が来ている環境が前提。**

ビルドした`BonDriver_BDA.dll`と`TBS6812.dll`を同じフォルダーに置き、BonDriverと同じ名前でINIを置く。
配置後はチャンネルスキャンをやり直す。

## 普段のモード

`[TBS6812] BoardModeHome`に、入力0,入力1の普段のモードを書く（S=衛星、T=地上）。
閉じた時にカードが空いていれば、このモードへ戻す。未指定なら閉じる時に書き込まない。

| 使い方 | 設定 | 普段できること | 統合版で足りない系統を選んだ時 |
| --- | --- | --- | --- |
| 4K中心（2ch） | `S,S`（テンプレートの既定） | S3 + S3、S3 + S | 地上波で`T,S`へ切替。もう一方の入力でS3やSも受信可 |
| 地上波と衛星を併用 | `T,S` | T + S3、T + S | 切替なし（再起動なし） |
| 地上波中心 | `T,T` | T + T、T + J.83B | 衛星で`T,S`へ切替 |

この設定を読むのは統合版のDLLだけである。S3だけを使い統合版を開かない環境では反映されないので、
`tools/tbs6812-board-mode.cpp`（引数なしで読み取り、`write 2 2`で書き込み）かメーカーのツールで設定する。

## 動作

地上系（ISDB-T / J.83B）と衛星系（ISDB-S）ではカードモードとBDAフィルターが違うため、同じグラフでは切り替えられない。
INIの`RebuildGraphForSystemType=1`により、空間の`DVBSystemTypeNumber`が変わる選局でグラフを作り直す。
ネットワークプロバイダーは、従来の単独設定と同じく系統ごとの専用のものを使う。

系統をまたぐ選局では次の順に処理する。

1. もう一方の入力の`Global\`セマフォ（BonDriver_BDAが使用中に保持するもの）を取得する。
   取れなければ別の受信が使用中である。選局は失敗を返し、今の受信は続ける。
2. モードを読み、選局先の系統の入力があれば書き込まず、その入力でグラフを作り直す。
3. なければ自分のグラフを閉じて両入力を確保し、必要な入力だけを変更する（地上は入力0、衛星は入力1）。カードが再起動する。
4. 読み戻しが一致するまで最大`BoardModeSwitchTimeoutMs`（既定45000 ms）待ち、デバイスを列挙し直してグラフを作る。
5. 失敗した場合は、元の系統のグラフを開き直せれば開き直し、選局の失敗を返す。

`OpenTuner`は書き込みをせず、グラフを作れる系統で開く。同じ系統内の選局ではカードを再起動しない。

## 制限

- どの入力もカード再起動を伴う変更は、両入力が空いている時しかできない。統合版で地上波を受信中に、もう1つ地上波は`S,S`では開けない。必要なら`T,T`にする。
- 閉じる時と、足りない系統を選んだ時に、それぞれカードが再起動する（各約1.5秒）。
- 異常終了した時は普段のモードへ戻らない。
- `BonDriver_BDA`を使わないアプリ（メーカーのツール、coaxdなど）の受信は検出できず、再起動で止めてしまう。
- 複数枚のカードでは、グラフを失った状態からの切替は、列挙順で最初に見つかった入力を対象にする。
- 再構築中の`GetTsStream`はデータを返さない。`WaitTsStream`はタイムアウトを返す。
- 給電できるのは入力0だけである。入力0を地上にした時の衛星受信は配線に左右される。

## 検証

- Release_Static x64ビルドと`tools/test-tbs6812.cmd`。INI振り分け、入力の空き判定、変更する入力、拒否時に受信を続けること、書き込みの順序、普段のモードへの復帰を確認する。
- `work/bon-driver-list.exe`でテンプレートを読み、UHF 40件、Opticast 109件、BS 26件、CS110 12件を確認した。

実機（2026-10-31、`bon-driver-probe`使用）：

| 確認内容 | 結果 |
| --- | --- |
| `S,S`で開いて地上波→BS→J.83B→CS | 全て成功（約8.8、4.2、8.1、5.0秒）。閉じた後は`2,2` |
| `T,S`で開いて地上波→BS→地上波 | 成功、カード再起動なし（2.9、4.3、6.0秒）。閉じた後は`1,2` |
| 統合版の地上波受信中にdantto4k（S3）を開く | 成功。相手の受信もエラー0 |
| 統合版の地上波受信中に2つ目の地上波（`S,S`） | 29 msで失敗を返し、相手の受信は継続 |
| 統合版で地上波を見て閉じ、dantto4kを開く | 成功 |
| モード書き込みから読み戻し一致まで | 約0.55秒 |
| 取得TS（先頭3 MiBを除く） | 同期・TEI・連続性エラー0、TSIDは0x7C11、0x7C12、0x4010、0x3017、0x6020で一致 |

以前の「両入力をそろえる」方式では、別プロセスが受信中のBS選局の失敗、地上波2系統の同時受信（`T,T`相当）、
TVTestでのチャンネルスキャンと地上波・光・衛星の視聴も確認した。

ロックの猶予は、BS→地上波で1回だけ公式ドライバー選局直後のロック確認に失敗した例を受けて入れた
（混在モードの地上系の準備で最大2秒）。再現頻度が低く、この修正の効果は確認できていない。

この方式でも、dantto4kと統合版の切替と視聴をTVTestで問題なく動かせることをユーザーが確認した（2026-10-31）。

**未検証:** EDCBでの録画、BonDriver_BDAを経由しないアプリとの競合、長時間録画、異常終了後の復旧、PC再起動後のモードの保持。
